- 2026-09-16: **"Go live" defaults to HTTPS polling, not a WebSocket** (measured from a browser page): `wss://api.mainnet-beta.solana.com` closes with 1006 and its HTTPS side answers 403 to a browser origin; `wss://solana-rpc.publicnode.com` accepts `logsSubscribe` then pushes nothing; `https://solana-rpc.publicnode.com` answers `getSignaturesForAddress` cross-origin in ~140 ms. So the page polls the 8 busiest pools every 12 s (×2 backoff on 429, ceiling 60 s) and keeps the socket as an opt-in mode for a paid/self-hosted endpoint.

- 2026-09-17: **The universe is monotonic** (`stocks/lib/universe.mjs`): Jupiter's search ranks over 100-record pages and the ranking moves, so re-running the same 118 queries dropped 24 of 441 known mints and added 30 while a direct `?query=<symbol>` still returned the dropped ones — a mint the run does not return is carried over with `seenInSearch: false` and each record keeps `firstSeenAt`/`lastSeenAt`. `removed-mint` in the change log therefore now means a mint really left the build. `firstSeenAt` for the 441 mints known on 2026-09-16 was seeded from that day's universe `fetchedAt`, nothing backdated further, and that founding cohort is excluded from the `newMints` feed because on the first recorded day "first seen" is a lower bound, not an arrival.

- 2026-09-17: **The built files are also loaded into Postgres** — schema `sonar` in the shared `geodata` database (`db/2026-09-17-sonar-stocks.sql`, `stocks/load-db.mjs`, `npm run stocks:db`, and a `db` step at the end of `stocks/refresh-on-server.sh` which now treats a missing `DATABASE_URL` as fatal like a missing `.env`). Four tables — `stock_issuer`, `stock_token`, `stock_token_snapshot`, `stock_trade` — each keeping the groupable facets as typed columns plus the whole source record as `jsonb`, because the static files cannot answer a *group by* across two of them or a question about yesterday. Two deliberate choices: the trade table **accumulates past the JSON's rolling 24 h window** and only ever refreshes `suspect` on a signature it already has, and every load is an upsert guarded by `IS DISTINCT FROM` on every loaded column, so an unchanged re-run does not even move `updated_at` (verified: second run touches 0 of 4,395 rows). Zero npm dependencies is preserved by shelling out to `psql` with each document as one dollar-quoted `::jsonb` literal whose tag is picked against the document's own bytes; the SQL builders (`stocks/lib/db-load.mjs`) are pure and tested as text, with one test asserting the inserted columns still exist in the DDL file.
- 2026-09-17: **`api/` is the first API — Hono on 127.0.0.1:3300, read-only over schema `sonar`** (`api/src/app.js`, its own `api/package.json` + committed lockfile: `hono` 4.13.8, `@hono/node-server` 1.19.17, `pg` 8.23.0; the repo root stays jest-only). `DATABASE_URL` comes from the environment via Node 24's `--env-file` (`node --env-file=../.env src/server.js` locally, `node_args: '--env-file=/root/code/rwa-sonar/.env'` under PM2), never from a hand-edited server file, and only the host and database name are ever logged. **The pages are NOT switched over** — `stocks.html`, `monitor.html`, `live.html`, `graph.html` and the cards still fetch the static `stocks-*.json` files, so the API is purely additive. It exists for what a file cannot answer: 22 facets that are also the 22 filter names (a facet's counts exclude its *own* filter, which is what makes faceted navigation work), per-day snapshot history, and the trade tape past the rolling 24 h window. The SQL builders (`api/src/lib/query.js`, `api/src/lib/facets.js`) are pure `(filters, facet) → {text, values}` and tested as text — no user input is ever concatenated, facet/sort names are whitelisted with a 400 rather than a silent default, and an unknown *filter* name is a 400 too because a dropped filter returns a wrong answer that looks right. One measured trap: node-postgres parses a `date` column into a **local-midnight Date**, which serialised `snapshot_date` as the previous day on a UTC+2 host, so `api/src/db.js` registers a DATE type parser that keeps the text Postgres sent.
