- 2026-09-17: **Every cited URL is now watched** (slice 1 of `stocks/EVIDENCE.md`): `stocks/extract-sources.mjs` walks the 12 dossiers plus `canonical-parties.json` and records every `http(s)` URL **with the field path that cites it** (`documents[3].url`, `findings[2].evidence`, prose in `redemption.fees`) into `stocks/data/sources.json` — 337 distinct URLs (266 html / 53 api / 18 pdf) deduped on a normalised URL that drops the fragment and `utm_*` but **keeps every other query parameter**, because `?alt=media&token=…` is the document; two citations written with an ellipsis are reported, never guessed at. `stocks/watch-sources.mjs` then fetches each one round-robin by host (1.5 s per host, conditional headers, 30 s timeout, 5 s/15 s backoff), normalises (PDF → `pdftotext -layout` on stdin; HTML → chrome stripped; JSON → **keys sorted**; anything else → watched as bytes), drops churn lines (bare dates, counters, cookie banners — but NOT a labelled `Last updated …`, which is the most informative line on a terms page), hashes, diffs (`stocks/lib/textdiff.mjs`: exact LCS under a 4M-cell cap, patience anchors above it) and mirrors the run into `sonar.source` / `sonar.source_version` / `sonar.change_event` (`db/2026-09-18-sonar-evidence.sql`; `claim` is slice 2). Four decisions worth keeping: a **bot wall is detected from the response BODY, never the headers** (every Cloudflare-fronted site sends `cf-ray` on a good 200 — a header check mislabelled most of the web on the first run); **`api` sources are capped at `info` severity** and raise no event, because a price endpoint changes by design and would bury the legal terms; **`gone` and `blocked` are findings, only `error` fails the run** (exit non-zero), so a permanently hostile host does not make a red run meaningless; and a source with no readable text plus a `<noscript>` notice is `blocked` as **javascript-only** rather than silently hashed — which is how both `url.prestocks.com` terms links were caught normalising to the single word "Notion". First run: 0 errors, 302 versions, **2 dead citations** (`remoramarkets.xyz` no longer resolves, and it is cited as the proof-of-reserves endpoint; one prnewswire 404) and 33 blocked on 18 hosts.
- 2026-09-17: **The watcher's UA is per host, and the SEC is the reason** (`HOST_USER_AGENTS` in `stocks/lib/watch.mjs`): a browser string keeps most bot walls down, but SEC access policy requires automated requests to declare who is asking, so `*.sec.gov` gets `rwa-sonar source-watch contact@rwasonar.com` — all 44 `sec.gov`/`archive.org` sources answer `ok` with it. Two more measured facts kept in code: **anonymous Wayback saves are refused** (`GET web.archive.org/save/<url>` → HTTP 500 with the Save Page Now form, reproduced with curl; 20 attempts, 0 archived, so `archive_url` stays null until there is an archive.org account key, and a pass gives up after 5 consecutive failures instead of spending 5 s of pacing each on 300 sources), and **archive.org's own 503s are recorded as `blocked`, not `error`** (`tolerates503`) after its availability/CDX APIs spent part of the day "temporarily offline" — one third party's maintenance window must not be indistinguishable from a broken watch, while every other host's 503 still reddens the run.
- 2026-09-17: **Every structured dossier field now carries the words it came from** (slice 2 of `stocks/EVIDENCE.md`): a claim is `{field, quote, url, locator, accessedAt, status, note}` in each dossier's `claims[]` — plus every `findings`/`incidents`/`attestations` entry that has gained a `quote`, which is a claim under the field `findings[3]` — shaped once in `stocks/lib/evidence.js` (UMD, so the page loads the file the builders import through `lib/evidence.mjs`), loaded into `sonar.claim` (`db/2026-09-18-sonar-claims.sql`, `stocks/load-db.mjs --only=claims`) and drawn as a `§` chip after every field's value on `stocks.html` and on the cards, with a hollow `§?` where a source is needed and missing. Measured across all 12 dossiers: **1,263 claims, 484 of 564 fields sourced** (851 confirmed / 354 unverified / 38 contradicted-corrected / 20 inference). Decisions worth keeping: **what needs a source is one JSON file** (`stocks/data/claim-fields.json`, 39 patterns, `vocabulary.*.value` expanded against each dossier's own keys and a path counted only where the record holds a value) read by the builders AND fetched by the page, so the coverage number cannot differ between a card, the built file and the panel; **coverage counts only `confirmed`** — an `unverified` or `inference` claim is a claim but not a source; an **`inference` has neither a quote nor a URL by construction** and carries a `note` naming what it rests on, so requiring quote-or-url silently dropped 8 real claims (the DDL checks are therefore "quote OR url OR note" plus "a `confirmed` claim must have a quote or a url"); the claim **id is content-addressed** (`<slug>:<field>:<sha1(url|quote) first 8>`) which makes a re-load a no-op upsert but leaves an orphan row when a quote is EDITED, so the loader counts and warns about rows no dossier offers any more and never deletes them; and `recorded_at` plus the two watcher timestamps are **insert-only**, because refreshing them from a dossier would make a stale claim look freshly checked. The card byte budget went 20 → **34 kB** (measured: min 24.0, median 29.0, max 31.5 kB fully sourced, against 13.7/17.9 before) after the chips were trimmed — the summary's `title` no longer repeats the quote the popover shows, and the inlined record carries the evidence summary only, since the claims are rendered above it and served in full by `/api/issuers/:slug/claims`. New API routes `/api/claims`, `/api/issuers/:slug/claims`, `/api/sources`, `/api/changes`, `/api/rules`; the same pass closed the three gaps `monitor.html` had listed — a **filter value containing a comma** is expressible as `?jurisdiction[]=…` (a repeated plain parameter is OR too, and neither form is comma-split), `worst_rule`/`venue_spread_pct`/`top1_share_pct` are sortable, and `health_status` sorts by **severity** rather than alphabetically.
